# ADR 0012: live クロックの先行は、消さずに吸収する

- 状態: 採用（2026-09-04）
- 関連: [0010](0010-two-repo-layout.md) / [0011](0011-verification-and-baselines.md) /
  clap-mml-play-server `docs/adr/0018-patch-load-must-not-spin-the-plugin.md` /
  clap-mml-play-server `docs/adr/0019-cache-player-slot-headroom.md`

## 何の話か

DAW の live 演奏（cache-player でキャッシュ WAV を鳴らす経路）で、
**小節の切り替わりで大きくモタる / 違う小節が鳴る**という報告があった。
2026-09-03 に**出た音そのものを WAV へ録って**調べ、原因は 2 つに割れた:

| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| A | 小節の頭の直後に音が 53.3ms 飛ぶ／小節の終わりの余韻が切れる | 音色ロードの前後の空回し `process()` 512×5 が、鳴っている voice の再生位置を進めていた | **直した**（play-server 側 `0018`） |
| B | 予約した小節とは違う小節が鳴る | 演奏ループがサーバーのサンプルクロックより先行し、先読みが**まだ鳴っていない小節のスロットを踏み潰していた** | **消さずに吸収する**（この ADR） |

A の直し方は play-server 側 `0018` にある。**ここに書くのは B の判断**。

## 先行がなぜ生まれるか（いまも真のまま）

`daw/src/playback/live_cache/timeline.rs` の `MeasureTimeline` は、
**「サーバーのサンプルクロックは実時間どおり 48kHz で進む」**という前提で
`Instant::now()` から発音位置を外挿する。

**この前提は音色ロードのたびに崩れる。** サーバーは state load のあいだ render を
回さないので、ロードにかかった実時間ぶんクロックが進まない。進まなかったぶんは
戻ってこないので、そのまま演奏ループの先行として積む。

実測（BPM113 / 1 小節 = 101947 frames = 2.124 秒）:

- 1 小節目の state load は冷えた状態で **3.10 秒**。そのあいだクロックは **0.26 秒**しか
  進まない。差の **2.7 秒 = 1.3 小節**がまるごと先行になる
- 定常状態でもスロット書き換えの clock 間隔は 101888〜102400 と揺れる
  （毎小節 ±450 フレーム程度の出入り）
- `prepare_ms` は **72ms〜3385ms と 50 倍ぶれる**（OS のファイルキャッシュと Surge の
  暖まり具合）。「ロードが遅いから壊れる」形の判定にしてはいけない

## 決定

**先行そのものは消さない。先行しても正しい小節が鳴るようにするだけにする。**

| 入れたもの | 何をするか |
|---|---|
| 開始時の原点合わせ（案 A・実装済み） | `MeasureTimeline::begin`（timeline を張る）と `start_clock`（クロックを起こす）を分け、**1 小節目の state load が終わってから**起こす。起こすまでサーバーは眠っていてクロックが 1 サンプルも進まないので、原点が揃う。**ロードに何秒かかっても `drift` は 0** |
| スロットの余裕（案 D・実装済み） | cache-player の `SLOT_COUNT` を 2 → 4。吸収できる先行が約 1 小節 → 約 3 小節になる（play-server 側 `0019`） |

### 見送ったもの

| 案 | 内容 | 見送った理由 |
|---|---|---|
| **B**（Stage 4） | サーバーへ現在の live clock を問い合わせ、外挿をやめる | **根治だが高い。** SHM のメーターにフィールドを足す＝**両 repo 同時のプロトコル変更**で、過去に版ズレで壊した事故がある。いまは A + D で症状が出ておらず、出たときは機械で検出できる |
| **C**（Stage 6） | state load を非同期 standby 経路（`PrepareStandbyLivePatch`）へ移し、クロックが止まる原因を絶つ | standby は「**同時 1 件**」契約で、DAW は 1 小節あたり 7 instance ぶんを出す。さらに standby は「鳴っていない bank へ出す」契約だが、DAW の 7 instance は **bank 0 と bank 1 に分かれて載っている**（実測）。鳴っている bank へ出すと `render_skips` が上がる。**読めない難所が 2 つ重なる** |

**どちらも「予防」であって「修理」ではない。** A・D を入れたあとの実測では、
症状（違う小節が鳴る／音が飛ぶ／余韻が切れる）はすべて 0 になっている。

## 残っているリスク（**ここが重要**）

### 1. 「ロードで render が止まる」は今も真

B の前提は消えていない。**A が直したのは「開始時の 1 回」だけ**で、
**演奏中に起きる先行は今も積む。** 消しているのではなく、D の余裕（約 3 小節 = BPM113 で
6.4 秒）で受けているだけ。

いま表面化していないのは、

- 定常状態の出入りが毎小節 ±450 フレームと小さいこと
- 実演奏のループ長が 4 小節で、**ループ長 <= `SLOT_COUNT` なら踏み潰しが起きない**こと
  （小節とスロットが 1 対 1 になるため）

の 2 つのおかげ。**演奏中のロードが極端に重い日**（プラグインが増える・キャッシュ WAV が
長くなる・別プロセスがディスクを掴む）が来れば、また出うる**構造的なリスク**として残る。

### 2. ループ長によっては余裕がほぼ無い

スロットは `小節 index % SLOT_COUNT` で決まるので、
**ループ長が `SLOT_COUNT` の倍数でないと折り返しで余裕が減る。**
数は `daw/src/playback/live_cache/tests/slot_headroom.rs` が固定している:

```text
余裕 = 無制限                        （ループ長 <= SLOT_COUNT = 4）
余裕 = SLOT_COUNT - 1 = 3 小節       （ループ長が 4 の倍数）
余裕 = (ループ長 % 4) - 1            （それ以外）
```

**5・9・13 小節のループは余裕 0。** 本数を増やしても消えない穴で、
消すにはスロットの選び方を「小節 index」から「**演奏した小節の通し番号**」へ変える
（`cues::measure_slot` と `PreloadedMeasure` を通し番号で持ち直す）必要がある。
今回は入れていない。

### 3. 先読みが外れた小節は取り消せない

AB リピートや演奏中の小節数変更で先読みが外れると、予約済みの note on は取り消せない
（もうサーバーへ届いている）。その 1 小節だけ「予測していた小節の頭が一瞬鳴り、
その直後に本当の小節が始まる」形になる。ログの `preload=miss` が目印。**仕様。**

## 再発したら最初に見るもの

**ログだけを見ても原因は出ない。** TUI もサーバーも「完璧」と報告し続けていた
（`late=0` / `prepare_ms=0.0` / `at_frames` の間隔がサンプル完全一致）。**出た音を録ること。**

```text
# 1) 混ざった出力を録って、予約した小節が鳴っているかまで測る
python scripts/capture_daw_live_mix.py --loop-measures 4 --measures 8 --tracks 9

# 2) hi-hat 1 本だけを聴こえる状態にして打点を 1 つずつ見る（鳴らす行は減らない）
python scripts/capture_daw_live_mix.py --only-row 6 --loop-measures 4 --measures 8 --tracks 9
```

出力の見どころ:

| 見出し | 見るところ | 正常値 |
|---|---|---|
| `== 原点の判定` | `drift` | **0 frames**。ロードに何秒かかっても 0。ここが `prepare_ms` に比例していたら開始時の原点合わせ（案 A）が壊れている |
| `== スロット上書きの判定` | `margin` と「余裕のいちばん薄いところ」 | margin はすべて正。余裕は**約 3.0 小節**。1.0 小節へ落ちていたら `SLOT_COUNT` が 2 へ戻っている |
| `小節ごとの照合` | `corr` / `lag` | `corr` 0.7 前後（`--only-row` なら 1.00）で `lag` の spread が 0。**`corr` が 0.4 台へ落ちたら違う小節が鳴っている** |
| `== 刻みの判定` | `drift_spread` / `gap_diff` | どちらも 0（許容 512 frames = 1 オーディオブロック） |
| `== 素材との突き合わせ` | 「切れている窓」 | 0 |

サーバーログ（`daw-live-mix-capture-server.log`）は
`cmrt-live-patch: event=apply instance=N clock=… patch=slot=S;…_measM.wav` を見る。
**DAW の先読みは非同期 standby 経路を通らない**ので、`cmrt-standby-load` の行は 1 つも出ない。

先行そのものを注いで A/B を取りたいときは、`MeasureTimeline::start_clock` の
`self.origin = Instant::now()` を過去へずらす（例: 2 小節ぶん = 4248ms）。
**演奏ループがサーバーより 2 小節先行している状態**がそのまま作れる。

再発が「演奏中のロードで先行が積む」形だと確かめられたら、**そのとき案 B を入れる。**
順序は B（外挿をやめる）→ C（クロックが止まる原因を絶つ）。
