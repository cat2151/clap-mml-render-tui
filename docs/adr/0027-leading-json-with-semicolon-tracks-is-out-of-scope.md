# ADR 0027: 先頭 JSON 付きの MML で「;」でトラックを分けた形は扱わない

- 状態: 採用
- 関連: [0003](0003-mml-patch-key.md)

## 決定

先頭 JSON（[0003](0003-mml-patch-key.md)）が付いた MML で、本体を「;」で複数のトラックに分けた形は、対応する入力に含めない。

- この形でどの音色・どの effect chain で鳴るかは保証しない。鳴る音が想定と違っても不具合として扱わない。
- 先頭 JSON を読む機能（音色の取り出し、effect chain、overlay への取り込みなど）を作るときや直すときは、この形を検出したりエラーにしたり、トラックごとに先頭 JSON を配ったりするコードを書かない。
- 調べている途中でこの形の挙動に気づいても、「未対応」「デタラメな音が鳴る」として報告しない。直す課題として挙げない。

## 理由

- 運用データにこの形が無い。config dir（`%LOCALAPPDATA%\clap-mml-render-tui`）の notepad 本文は 42 行すべてに先頭 JSON が付いているが、「;」を含む行は 0 行だった。history・DAW・daily のページにも「;」は 1 つも無い。
- 先頭 JSON は「行 1 つに音色 1 つ」を表すために使われている。複数のトラックは notepad の別の行や DAW の別の track で書くので、1 行の中でトラックを分ける必要が無い。
- 使われていない形に対応すると、先頭 JSON を読む箇所のそれぞれに分岐とテストが増える（YAGNI 違反）。

## 却下した案

- **「;」を検出してエラーや警告を出す。** 誰も書かない入力のための分岐とテストを、先頭 JSON を読む箇所ごとに持つことになる。
- **先頭 JSON を全トラックに当てる、またはトラックごとに JSON を書けるようにする。** 求められていない書式を作ることになり、MML の解釈がライブラリ側と二重になる。

## 結果

- この形を書いた場合は、ライブラリ（`mmlabc_to_smf`）の解釈のまま、どの音色で鳴るか分からない状態で鳴る。
- 運用データにこの形が現れたら、この ADR を見直す。
